# 07 · 部署与联调清单

> 目标：把 factlayer 跑起来，两台 DSH 机器都指向同一个 shim，验证写入回执与检索闭环。
> 前置：三层代码已入库（`c5ec5db`），181 Python + 70 TS 测试全绿。

## 0. 架构落位

```
Windows DSH (192.168.168.1)  ──┐
                                ├── HTTP ──→ shim（FastAPI + SQLite + embedding 调用）
网吧 VM DSH (192.168.168.8)  ──┘              建议跑在阿里云 ECS (192.168.168.2)
                                              数据目录：/var/lib/factlayer/facts.db
```

- shim 是**唯一**写入方/读取方，SQLite 只被它打开；两台 DSH 只发 HTTP。
- embedding 由 shim 单点调用（`qwen3.7-text-embedding`，1024 维），密钥只存在 shim 的 `.env`。

## 1. shim 部署（以 Linux/ECS 为例）

```bash
# 1) 取代码
git clone <repo> /opt/factlayer && cd /opt/factlayer

# 2) Python 环境
python3 -m venv .venv && . .venv/bin/activate
pip install fastapi uvicorn httpx numpy pytest

# 3) 配置（密钥只写这里，权限 600）
cat > /opt/factlayer/.env <<'EOF'
DSH_FACT_DB_PATH=/var/lib/factlayer/facts.db
EMBEDDING_BACKEND=openai-compat
EMBEDDING_BASE_URL=https://<你的 embedding 端点>/compatible-mode/v1
EMBEDDING_MODEL=qwen3.7-text-embedding
EMBEDDING_DIM=auto
EMBEDDING_API_KEY=<你的密钥>
RETRIEVAL_ROUTES=vector
ADMIN_TOKEN=<随机串>
FACTLAYER_SPACE_ID=factlayer-default
EOF
chmod 600 /opt/factlayer/.env
mkdir -p /var/lib/factlayer

# 4) 起服务（先前台跑，确认再上 systemd）
cd /opt/factlayer && .venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

systemd 单元（确认可跑后再建）：

```ini
[Unit]
Description=factlayer shim
After=network-online.target

[Service]
WorkingDirectory=/opt/factlayer
EnvironmentFile=/opt/factlayer/.env
ExecStart=/opt/factlayer/.venv/bin/uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000
Restart=always
User=factlayer

[Install]
WantedBy=multi-user.target
```

> ⚠️ 绑 `0.0.0.0` 仅在 shim 前面有防火墙/内网限制时；否则绑 `127.0.0.1` + 反代。`ADMIN_TOKEN` 非空时 admin 端点要求 Bearer。

## 2. 部署后自检（不装插件也能做）

```bash
curl -s http://<shim>:8000/health | jq .        # status:"ready"，各 stage pending 应为 0 或很小
curl -s http://<shim>:8000/spaces | jq .        # [{"id":"factlayer-default","name":"factlayer"}]

# 写一条
curl -s -X POST http://<shim>:8000/memories -H 'content-type: application/json' -d '{
  "content":"测试：我家车位在 B1 区 A17",
  "session_id":"factlayer-default",
  "source_client":"manual-test",
  "client_write_id":"<uuid4>"
}' | jq .

# 查一条（应命中，且带 score 与 recorded_at）
curl -s -X POST http://<shim>:8000/search -H 'content-type: application/json' -d '{"query":"车位在哪","limit":4}' | jq .
```

验收点：
- 写入返回 `{id, seq, recorded_at, client_write_id}`，**无报错**；
- `/health` 的 `pending.embedding/fts` 很快归 0（派生循环或写入即索引）；
- `/search` 命中刚写的记录，score 为数值。

## 3. 装插件（DSH 侧）

provider 包不能走 GUI 安装器。两条路：

**A. 本机开发用（已实证）**：junction 安装，不动 `package.json`/lockfile
```powershell
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-mnemon-provider-factlayer" `
  -Target "E:\dsh-mnemon-provider-graphiti\plugin"
```
包自身的 peer 依赖（`dsh-mnemon-source-memory-spaces`、`dsh-mnemon`）需要在 `plugin/node_modules` 建 junction 指向 profile `.pnpm` 里的实际目录。

**B. 正式发布**：随 dsh-mnemon 的 bundle patch 内置。

### 3.1 patch 写在哪（最容易错的一处）

`providers` 属于 **`mnemon-source-memory-spaces` 子插件**的 `config`，**不是 `mnemon` 主插件**。写在 `mnemon` 下不会报错，只会被静默忽略（第一次联调因此白折腾一轮）。

```yaml
- id: mnemon-source-memory-spaces
  name: dsh-mnemon-source-memory-spaces
  config:
    providers:
      # ⚠ 必须把 bundle 里的 9 个默认 provider 全部重复一遍，再加 factlayer
      - use: dsh-mnemon-provider-mnemon-native
        instanceId: mnemon-native
      # …openviking / honcho / mem0 / hindsight / holographic /
      #   retaindb / byterover / supermemory 同理…
      - use: dsh-mnemon-provider-factlayer
        instanceId: factlayer
```

- patch 整块替换 `config`；漏写任何一个默认 provider，对应空间都会从 Memory 页消失。
- **改 patch 要重启后端才生效**（实测热加载没有应用这份配置）。
- 生效判断：日志出现 `patch: entry ... not found` 或 `name mismatch` 就是条目名不对。

### 3.2 启动脚本的 3080 双监听坑（已修，备查）

3080 上可能有两个监听：`127.0.0.1:3080`（DSH 后端）与 `192.168.168.1:3080`（远程转发器）。启动脚本若只按端口取第一条，会杀掉转发器、后端不动，表现为"重启失败但进程时间变了"。修法：优先 `127.0.0.1`/`::1`，并排除转发器进程。

## 4. 第一次端到端验证

1. Memory 页出现空间，`status` 为健康（不是 "starting/rebuilding"）。
2. 让模型记一条：`记住：我下周五去体检`。
3. **检查回执**：工具结果里 `action` 必须是 `stored`（或 committed/计数），**不能是 `unknown`**——`unknown` 说明回执翻译没生效，记忆其实写了但模型被告知没写。
4. 让模型查：`我什么时候体检？` → 应命中并给出记录日期。
5. 停 shim → 再查 → 模型应看到 `unavailable` 且文案以 `NO_MATCH` 开头，**不是空列表**；恢复 shim 后自动恢复。

## 5. 两台机器

- 两台都装同一个插件、`baseUrl` 指向同一个 shim。
- `memoryBodyId` 由 discover 自动写入 `connection`，**不需要手工填**；两台拿到的值相同（来自 shim 的 `/spaces`）。
- `session_id` 取该值 → 两台写入落在同一 session 分组；`/search` 不按 session 过滤，所以互相可见。
- 验证：A 记一条 → B 查得到。

## 6. 回滚

- 插件：从 `cordis.patch.yml` 删掉 factlayer 段并重载（数据不受影响）。
- shim：停服务即可；SQLite 是唯一事实源，**升级/迁移前先跑 `/admin/backup`**（备份是硬需求）。
- 数据迁移：旧库升级会自动重建索引；若 `/health` 报 `migration_needs_rebuild:true`，跑 `POST /admin/rebuild`，直到 `index.gap == 0`。

## 7. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| Memory 页空间一直 unhealthy | status 拿不到 / 插件装配失败 | 看 DSH 日志；`curl /health` 是否 `ready` |
| 模型说"没有这条记忆"但库里有 | 检索未命中或向量路熔断 | 看 `/health` 熔断状态与 `degraded` 标记；查 `/admin/search?query=` |
| 写入后模型说 action unknown | 适配器回执没生效 | 查插件版本与 `action` 字段；重装 `plugin/` |
| `/search` 返回 503 rebuild | 正在重建索引 | 等待完成；`/health` 的 `rebuilding` 变 false |
| 检索结果少得异常 | 向量路降级到 bigram | `tags` 里有 `vector-unavailable`；查 embedding 端点 |

## 9. ECS 部署实录（2026-11-12）

**环境**：阿里云 ECS `i-2ze07ji23vhqjm1nwrb9`（Debian 13，Python 3.13），EasyTier 地址 `192.168.168.2`（tun0）。
**访问方式**：本机装了 `workbench` CLI（阿里云 Workbench），`workbench list -r cn-beijing` / `workbench exec -i <id> -c "..."` / `workbench upload`。**不需要公网 SSH**。

**踩到并解决的三件事**：

1. **ECS 上 `git clone` GitHub 失败**（`GnuTLS recv error (-110)`，TLS 被中断）。改用 `workbench upload` 传 `app/` 的 tarball，再解包部署。
2. **nftables 默认 drop**：服务绑 `192.168.168.2:8000`，但 input 链没有 8000 规则。已加并写进 `/etc/nftables.conf`：
   `iifname "tun0" ip saddr 192.168.168.0/24 tcp dport 8000 counter accept`
   （只对 EasyTier 内网开放，公网不可达。）
3. **本机访问 ECS 的内网地址必须绕过 Clash 代理**：`Invoke-RestMethod -NoProxy`，否则会走代理拿到 502。

**部署结果**：`/opt/factlayer`（venv + app）、`/var/lib/factlayer/facts.db`、systemd `factlayer.service`（`--host 192.168.168.2 --port 8000`，`Restart=always`）。`/health` ready，写入→向量召回闭环通过。

**Windows 端切换**：`~/.mnemon/state/memory-providers.json` 的 `services.factlayer.baseUrl` 改为 `http://192.168.168.2:8000`，**必须重启后端**才生效（运行中缓存旧地址；改文件不会热更新）。改前已备份。

**第二台机器（网吧 VM）**：网络可达（VM 能 curl 通 ECS health），但安装插件需要 `dsh` 用户或 root 权限——`zhb` 读不到 `/home/dsh/.dsh` 且 sudo 需密码，待用户提供执行通道。
