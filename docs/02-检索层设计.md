## 0. 一句话

**事实层不动。检索层只保留有证据的路线：一条与实测基线同构的二元组路（出厂唯一开启），被作废的记录由存活纠正者在路内顶替，排除只发生在出口。出厂默认即可用、可复现、零外部依赖。**

## 1. 实测基线

语料 119 条 / 题库 40 题；随机基线 R@6 = 0.0505。

| 路 | R@6 | R@10 | MRR | 覆盖@50 | 空结果 |
|---|---|---|---|---|---|
| R2 二元组（单列） | **0.4875** | 0.5000 | 0.6269 | 0.5000 | 2/40 |
| R1 向量（TF-IDF 替身） | 0.4583 | **0.5333** | 0.6051 | **0.6667** | 0 |

## 3. 基线同构的索引规格（B2/B3 + N6/N8）

### 3.1 出厂索引：单混合列，逐字复刻基线

`research/recall/recall_eval.py::bigrams_of` 就是规格（已核对源码）：

```
对 content 做 NFKC
按码点切段：CJK 连续段 / Latin+数字连续段 / 其他（标点空白）
CJK 段：len == 1 → 产出该单字；len > 1 → 产出该段全部双字（不产单字）
Latin 段：整段小写，作为一个 token
全部 token 空格连接，写入【同一个】bg 列，一个 FTS5(unicode61) 索引
```

- **不拆两列**：拆列会改变 BM25 的 IDF 与文档长度归一，排序不再等价，"逐字节复刻"失去意义（B2）。
- "单字+双字"的早期设计作废：基线只在 CJK 段长度恰为 1 时产单字；这也是 2/40 空结果的来源。
- 分词函数必须是全函数：非法代理对、超长文本不抛异常（派生失败=写入失败）；`content` 设长度上限，超限在写入层显式拒绝。
- 写入即索引：ngram 派生与事实写入同一事务，不允许"写进去了搜不到"。

### 3.2 查询构造与复刻验收（N6）

- 主路径逐字复刻 `bigrams_of(content)` 的查询侧：同一函数、同一分段、CJK 双字 OR（孤立单字段产单字）、Latin 整词；转义双引号，禁用 NEAR/AND/NOT/`*`。
- **Golden fixture**：`research/recall` 一次性生成 fixture（每题基线查询串 + 预期 top-6 + sha256 + 基线 commit），提交进产品仓库；产品测试用自己的构造器重算并断言逐字节相等，运行时不依赖 research 代码。**fixture 必须列出 2/40 空结果那两题的 id 与查询串**，确认确属"查询仅含单字（或 CJK 段全为单字）"——目前是文档推断，未见证据。
- 转义若改字节：分别存档"转义前 token 序列"与"转义后最终串"两份黄金文件，并对基线语料断言转义恒等。
- 空查询保护：token 数 0（极端输入）→ 直接 NO_MATCH，不构造空 MATCH 表达式。
- 查询 token 上限 200，截断计数。

## 4. 作废与纠正（B1 + B4 + B5 + N1/N2）

### 4.1 唯一最终集合 hidden（B5 + N2）

同一只读事务内计算，**不做单独的 cycle_pardoned**：

- `voided_initial`：per-pair 最新边（`ORDER BY id DESC`，`supersedes.id` 为 AUTOINCREMENT）为 supersede 的 to_id。
- **`hidden = { x ∈ voided_initial : 沿纠正者边在 ≤20 跳内可达某个 ∉ voided_initial 的节点 }`**
  - 可达不到存活节点（成环、或 20 跳触顶）的 voided 节点**一律不 hidden**，进入 pardoned，按「循环裁决 / 链过长」展示。
  - 这样同时堵住"20 跳触顶时被静默 hidden"的洞。
- **反例验证（必须写进测试）**：A↔B 成环、外部 C 纠正 A 时，A 与 B 的真实链头都是 C，应替换为 C，而不是赦免 B。
- `hidden` 是**全系统唯一口径**：路内替换、出口断言、"另有 N 条"计数、日志、`/health` 全部只用它。
- 写入拒环检测只看「最新边为 supersede 的图」，revoke 边不参与；仅在新增 supersede 边时检测。
- 现有 `app/voided.py` 的纠正链是 3 跳且超限直接丢弃，需对齐到 20 跳 + 不丢弃。

### 4.2 各路检索**不**排除（B1）

各路取**含 hidden 的**原始 top-K。SQL 层不得排除；`hidden` 只用于：路内替换、出口断言、被隐藏匹配计数。向量路先取 top-K 再替换，不预先 mask。

### 4.3 路内替换（RRF 之前）

```
每路取原始 top-K（含 hidden 成员）
  → 命中 A ∈ hidden：用 live_head(A) 占据 A 的原始名次，A 移出该路列表
  → 路内去重：同 id 取最佳名次，每路每 id 至多一票
  → 按（名次 asc, gseq desc）确定性排序 → 截断 50
  → 进 RRF
```

- 跨路各得一票是正当多路证据；同路绝不重复计票。
- 被作废项只当"位置提供者"，不进 RRF、不参与打分；替换后不重排名次。
- 多个存活纠正者并列继承 A 的名次；输出按 gseq 新→旧，标「取代 id=A」。
- 因取代入选（文本不含查询词）也打标签，防误解为自身匹配。
- FINAL_K=4 是替换后的 4，纠正者占名额。

### 4.4 环（B4）

- **写入时拒绝成环**：新边若在 (from→to) 图产生环（含自环），同一写事务内检测，返回 409「该裁决会形成循环，已拒绝」，原文错误只进日志。
- **读路径防御**（历史数据）：环整体在 RRF 只算一票（环内最佳名次）；**FINAL_K=4 上限优先**——正文最多展示 3 个最新成员，其余**列出 id 清单**（受 4800 总字符预算约束，见 §5.1）并注明可用"按 id 取全文"接口取回（01 已有；对 reader 是否可达见 03 §5/§6）；全部标「循环裁决」。
- 链：安全阀 20 跳，触顶输出已到达节点并标注，不丢弃。

### 4.5 出口断言

最终输出若含 `hidden` 成员且不属于豁免（`include_superseded=true` 的显式请求）→ 丢弃、计数、ERROR 日志（带 query id 便于复现）、测试失败。丢弃是设计内行为，不算静默丢；但触发即说明替换逻辑有 bug。

## 5. 融合与输出（按契约收敛，见 03）

```
快照(hidden, live_head)
  → 每路：top-50（含 hidden）→ 路内替换 → 去重 → 排序 → 截断
  → RRF(k=60) → 同分 gseq 大者优先 → 取 FINAL_K=4
  → [会话展开：默认关；开启时只能占用 4 条名额内]
  → 每条 content ≤1200 字符；总字符预算 ≤4800
  → 出口断言
```

**契约约束（03 §6，P0，必须遵守）**：

1. **`FINAL_K = 4`**（不是 6）：provider-native 下所有结果 tier=ranked，`strict-v1` 的 `maxRankedResults` 默认 4。若要 6 条，须把 `recallQuality.maxRankedResults` 配到 ≥6，二者取一并写进部署文档。
2. **输出上限 12 条 / 12000 字符不可达**：策略侧实际是 6 条 / 单条 1200 / 总 4800（首查 4 条 / 3600）。设计按 **4 条、单条 ≤1200、总 ≤4800** 收敛。
3. **每条结果必须带数值 `score`** 并声明 `scoreSemantics: provider-native`；缺 score → tier unknown → 最多 2 条且每回合只收 1 条。score 只是定档用，模型看不见，**不承载语义**。
4. **`createdAt` 必须是 ISO 8601 字符串（UTC）**；给数字会被静默丢弃。
5. provider-native 时排序按 Provider 返回顺序、分数不参与排序——**RRF 顺序直接生效，无需归一化**。

### 5.1 状态通道（03 §4：状态与结果不可兼得）

契约事实：provider 的 `hint` **只在 `results` 为空时**才转成 `evidence.unavailable` 透给模型；结果非空时 hint 被丢弃。

| 语义 | 落点 | 说明 |
|---|---|---|
| `NO_MATCH` + 路状态摘要 | `results: []` + `hint` | hint 唯一能透传的场景；文案必须**以 `NO_MATCH` 开头**（键名叫 unavailable，防模型误读为故障） |
| `weak` | `tags: ["weak"]` | 无字段；靠 score 表达等于白做（模型看不见 score） |
| 被隐藏匹配计数 | **首条 `content` 尾行** + `tags:["hidden:N"]` | 结果非空时唯一通道；**丢弃即静默误导** |
| 来源路 / 展开项 / 因取代入选 | `tags`：`via:bigram`、`expanded`、`superseded-by:<id>` | tags 上限 8 个、每个 300 字符；**不用逗号**；状态标记优先占用 |
| `include_superseded` | **不可达**，降级为 **admin 端点**（`ADMIN_TOKEN`） | 请求侧三层白名单，参数进不来；只作运维/评测能力 |
| 最近分区 | **删除** | 与 NO_MATCH 互斥：返回最近项 → 结果非空 → 状态全丢 |
| 展开/截断丢弃的 id | 首条 `content` 尾行或 `tags` | 受 8 tag / 300 字符 / 4800 总预算约束 |


## 6. 排序与单调序（B3 + N1）

- **命名冲突规避**：`seq` **保留现有含义**（会话内 0 起连续序号：写入回执、按会话排序、会话展开、`idx_memories_session(session_id, seq)`、并发测试都依赖它）。全局单调序改用**新列 `gseq`**：
  - `gseq INTEGER PRIMARY KEY AUTOINCREMENT`（rowid 别名），`id TEXT` 保留为对外稳定标识（`UNIQUE NOT NULL`），`seq` 语义不变。
  - 理由：隐式 rowid 会被 `VACUUM INTO` 重编号、删除最大行后复用；显式 INTEGER PRIMARY KEY 的 rowid 与 `sqlite_sequence` 在 VACUUM 后保留。
- tie-break：**`gseq DESC`**（新者优先）；跨会话比较只用 gseq，绝不用 `seq`。不采信客户端时钟。
  - **实测注记（v8 实现）**：bigram 路的**原始 FTS 名次**沿用基线
    `bm25 ASC, rowid ASC`（rowid == gseq，天然升序）。BM25 同分并列若改成
    `gseq DESC` 会翻转基线 top-6（实测 R@6 降到 0.4750，低于 0.4875 验收线）；
    因此「一律 gseq DESC」适用于 RRF 同分、输出排序、路内替换/多纠正者排序，
    **bigram 原始名次是复刻基线的硬约束，单独保留 rowid ASC**。R1/R3 等其余路仍用 gseq DESC。
- `supersedes` 最新边：**只按 `id DESC`**（AUTOINCREMENT），不依赖 `recorded_at`（时钟回拨会选错边）。
- 迁移（SQLite 改 PK 必须重建表）：先 DROP 防写触发器与 FTS 触发器 → 重建表（`INSERT … SELECT` 时按 rowid 显式填 `gseq`）→ 重建 FTS（external content `content_rowid=rowid` 与 bigram 虚表 rowid 因此稳定，附带收益）→ 重建触发器与索引 → 写 `migrate_memories_gseq()`。无生产数据时也可"删库 + 派生重建"，但必须写进 README。
- 从旧备份恢复后 `sqlite_sequence` 会回退：内存向量矩阵按 `gseq` 对齐，恢复后必须全量重载。

## 7. R1 向量路（默认关；B7 + N4）

- 模型可配置：`EMBEDDING_BACKEND=openai-compat|local-onnx`；`EMBEDDING_MODEL` 必填、启动校验；`EMBEDDING_DIM=auto`（首次调用推断落 meta 表，之后校验）。
- **内存矩阵一致性（B7）**：写事务提交后**增量刷新**内存矩阵（新增/替换该行向量），无 embedding 行的记录同时被排除在 R1 候选之外；矩阵与 DB 用 gseq 对齐并定期校验。启动时全量载入。
- 后端单点计算，客户端只发文本；按行存 `model_id + dim`。
- 模型变更：后台重算（断点续跑、限速、预估总量），超 `EMBEDDING_MAX_SPEND_USD`（默认 0.50）暂停并告警，人话措辞：「向量重建已暂停：已完成 1200/1900 条，已花 $0.50（上限）。回复"继续"可追加预算。」同一告警每会话一次，`/health` 存完整版。
- 维度不符但模型未变 → R1 关闭 + 告警，不自动重建。
- 故障降级：单次 3 秒超时、连续 3 次失败熔断 5 分钟；**告警写入模型可见通道**：结果为空时进 `hint`（`NO_MATCH` 之后另起一行），结果非空时进首条 `content` 尾行 + `tags:["vector-unavailable"]`（hint 在结果非空时会被契约丢弃，见 03 §4.1）。

## 9. 验收标准

1. **基线精确再现**：产品构造器对全部 fixture 查询串逐字节相等；R@6 = 0.4875（容差 ≤0.01，即一条不能翻）。确认 gseq tie-break 不翻转基线结果；翻转则查因，不放宽容差。
2. **变体门槛**：任何对基线构造的改动（单字兜底、uni/bi 两列、两列合并策略）都必须单独跑基准 ≥0.4875 才允许出厂；共用同一 harness 与门槛，禁止变体套变体。
3. **R1 开关门槛**：真实 embedding 重测后 R@6 +0.05 且 bootstrap 95% CI 不含 0，才进默认。
4. **作废一致性**：性质测试——输出 ∩ hidden ⊆ 豁免集；环成员不在 hidden；revoke 恢复可检索；同毫秒 revoke→supersede 以 id 有序。
5. **路内替换**：A 被作废且命中 → 纠正者占 A 名次、不超额；A 被两路命中 → 纠正者两票；同路不重复计票；多纠正者并列；"因取代入选"标签存在。
6. **环**：写入成环 409（含自环）；历史环只算一票、正文最多 3 个、其余列 id、标注存在；FINAL_K=4 上限优先。
7. **gseq**：`VACUUM INTO` 后 gseq 不变；迁移回填正确；tie-break 可复现；`seq`（会话序号）语义不受影响。
8. **契约合规**：每条结果带数值 score 且 adapter 声明 `scoreSemantics: provider-native`；`createdAt` 为 ISO 8601 UTC；结果非空时状态只能走 tags/content 尾行（weak、hidden:N、via:、superseded-by:）；结果为空时 hint 以 `NO_MATCH` 开头并带路状态；**admin 端点**可查 `include_superseded`（模型路径不可达，验证项改写）。
9. **中文查询**：1 字、2 字、标点、数字、Latin 混合；FTS5 语法字符不报错不改义；超长截断计数；空 token → NO_MATCH。
10. **写入即索引**：写入成功立即可检索。
11. **重建**：整个重建在一个写事务内（数据量小）；查询始终看到完整旧/新索引；期间写入不丢。
12. **金丝雀**：用与产品一致的 NFKC+分段构造器抽子串（单 CJK 段 ≥6 字，不跨标点），N=20，连续两次失败率 ≥20% 告警；只对 bigram 路严格断言；标 canary 不计统计；失败记录 id。
13. **预算**：单条 content ≤1200 字符（含截断自报），总 ≤4800；超出时按 §5 的 tags/content 通道报告丢弃量，不静默。

| 配置项 | 默认 |
|---|---|
| `EMBEDDING_BACKEND` / `BASE_URL` / `API_KEY` / `MODEL` / `DIM` | openai-compat / 空 / 空 / 空 / auto（启用 R1 必填） |
| `RETRIEVAL_ROUTES` | `bigram` |
| `EMBEDDING_MAX_SPEND_USD` | `0.50` |
| `ADMIN_TOKEN` | 空（空则仅回环） |

代码常量：RRF_K=60、ROUTE_TOP_K=50、**FINAL_K=4**（契约 strict-v1 默认 maxRankedResults；要 6 条需同时把策略配到 ≥6）、ITEM_MAX_CHARS=1200、TOTAL_MAX_CHARS=4800、R1_TIMEOUT=3s、熔断 3 次/5min、链上限 20、查询 token 上限 200、金丝雀 N=20/20%。

生成侧配置（`LLM_*`）不属于本层。

## 12. 明确不做

ANN、FalkorDB 承接全文/向量、Graphiti k=1 RRF/一次性 MMR、RRF 加权、学习排序、cross-encoder 重排、分词扩展 `simple`、写入时 LLM 判断、冲突检测、软删除、运行时质量自动降级、把"拒绝检索"当模型不匹配响应。

## 13. 风险

1. 规模外推：融合无增益结论来自 119 条，数千条必须重测（发布时离线）。
2. 单路出厂：默认只有 bigram，同义改写查不到；配置 R1 并重测是必要动作。
3. 子串极限：bigram 对同义改写无效。
4. golden 口径：标准集是相关上下文，端到端评测要换口径。
5. 语料外发：R1 API 形态会把原文发给第三方 embedding 服务；local-onnx 可避免但需 90MB 冷启动，README 必须写明。
6. 环：写入拒绝后以 409 暴露，UI 文案需解释"这两条不能互相作废"。
7. 繁简：不转换 = 静默 0 命中，用 /health 繁体占比可观测。
8. 变体轨道：任何"更好的分词/更多列"都要过同一门槛，否则容易凭直觉上复杂方案。
