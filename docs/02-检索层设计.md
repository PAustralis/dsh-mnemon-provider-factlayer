## 0. 一句话

**事实层不动；检索层是一组可独立开关的召回路线，用机械规则（RRF）融合，再按机械规则（MMR、会话展开、作废过滤）裁剪。每一路都能关掉且不丢数据。**

## 1. 实测基线（必须记住的数字）

语料 119 条，题库 40 题，golden 映射 119/119。随机基线 R@6 = 0.0505。

| 路（本文编号） | R@6 | R@10 | MRR | 候选池覆盖@50 | 空结果题数 |
|---|---|---|---|---|---|
| R2 二元组 bigram | **0.4875** | 0.5000 | 0.6269 | 0.5000 | 2/40 |
| R1 向量（TF-IDF 替身） | 0.4583 | **0.5333** | 0.6051 | **0.6667** | 0 |
| R3 trigram | 0.1750 | 0.1750 | 0.3083 | 0.1750 | 24/40 |
| R6 最近 50 条 | 0.0667 | 0.1062 | 0.0974 | 0.4479 | 0 |
| unicode61 基线 | 0.0000 | 0 | 0 | 0 | 39/40 |

关键结论（bootstrap 2000 次）：

1. **31 种融合组合，没有一种在 R@6 上超过最好的单路**（最高持平 0.4875；四路全开 0.4583）。
2. **RRF 收益不显著**：所有"融合 − 二元组"的 95% CI 都跨 0。
3. **最近 50 条显著有害**：二元组 + 最近50 = −0.0979 [−0.1646, −0.0333]。
4. **MMR 增益 = 0**（25/31 组合一字不差）。
5. **RRF k 不敏感**（10/30/60/100 恒定）。
6. 唯一正向收益在排序质量：向量+二元组 MRR 0.6348 vs 0.6269。

机理解释：119 条库里 top-50 已覆盖 42% 的库，长尾把 RRF 分数量纲压平，精确命中被稀释。**数千条规模下机理变化，必须重测**。

### 1.1 局限（不得越过）

- **向量路是替身**（无 ONNX，用字符 2–3gram TF-IDF 余弦）："向量与二元组覆盖包含、互补性 0"与"MMR 惰性"**不得推广**到真实 embedding。
- 119 条规模小；40 题粒度 0.025/题，**≤0.05 的翻转不当结论**（含"trigram 作融合信号有 −0.0333 边际价值"这一条——它低于本文自己的门槛，只能算观察）。
- **R6 与实测 R4 不同源**：实测 R4 用 `raw_date`（内容日期）排序，R6 用 `recorded_at`（真实写入时间）。所以"最近路有害"的实测**不直接适用**于 R6；R6 兜底仍保留，但它是低风险假设而非实测结论。
- golden 是"当年人工挑的相关记录"，不是唯一答案集；4 题问的事实 golden 里不存在；4 个场景是"1 条真相关+5 条干扰"，指标在此奖励噪声。

## 2. 六路清单

| 编号 | 路 | 出厂状态 | 依据 |
|---|---|---|---|
| R1 | 向量（模型可配置，默认 1024 维 API 形态） | 开 | 覆盖率最高；真实 embedding 待重测 |
| R2 | 二元组全文（单字+双字影子列） | 开（主力） | R@6 0.4875 最高 |
| R3 | trigram 全文 | 关（观察，留开关） | 单路差（0.175）；"作融合信号有 −0.0333 边际"低于本文 0.05 显著性门槛，且双字 bigram 是 trigram 命中能力的超集——出厂关，留开关 |
| R4 | 图邻居（FalkorDB 1 跳实体邻居） | 默认关 | 无实测数据 |
| R5 | 纠正后补（事件驱动，非常驻池） | 开 | 治"纠正记录沉底"，见 3.5 |
| R6 | 最近 50 条（兜底） | 兜底 | 见 1.1：实测不直接适用，低风险假设 |

## 3. 各路实现规格

### 3.1 R2 二元组全文（主力）

- 派生表 `memories_ngrams(memory_id, ngram_text)`（**派生层，可弃可重建**；不在 `memories` 加列，事实表结构不动）。生成规则：`content` → NFKC 归一化 → 按位置输出 **单字序列 + 双字序列**（空格分隔），保留原顺序；不转繁简、不切标点、不删数字（数字与 Latin 连续段按原样保留为单 token）。
- FTS5 虚表 `unicode61` 索引 `ngram_text`。
- **查询构造器冻结（关键）**：实测拿到 0.4875 的构造器就是基线，出厂实现必须**逐字复刻**它，并在改写前后各跑一次基线；任何改动先证明不低于基线。构造规则：
  1. 双字短语优先：`"ab" OR "bc" OR ...`（按位置切双字）
  2. **短语 0 命中 → 自动回退 OR 单字互连**，且回退必须计数+打日志（不许静默 0 命中）
  3. 查询串 < 2 字时直接走单字
  4. 中文标点、Latin-Han 边界、数字串按"原样成段"处理，规则写进测试用例（包含 NFKC 全角转半角、零宽字符剔除）
- 索引体积约原文 2–3 倍，数千条规模几 MB，可接受。

### 3.2 R1 向量

- **模型可配置，维度由模型决定**：`EMBEDDING_BACKEND=openai-compat`（默认）或 `local-onnx`；`EMBEDDING_MODEL` 必填、启动时校验非空；`EMBEDDING_DIM=auto`（默认）→ 首次调用取 `len(vector)` 写入 `meta` 表，之后每次调用校验一致。
- **后端单点计算**：只在 shim 侧算，两台客户端只发文本。跨机漂移因此结构性不存在；`model_id + dim` 校验用于防"换了模型却沿用旧向量"。
- **不符时：拒绝检索 + 单命令重建**（`POST /admin/rebuild`），**不做自动重建**——自动重建会对全库打 API，等于静默花钱。
- 存储：`embeddings.vector` BLOB，float32 小端，写入时 L2 归一化（点积即余弦）。
- 检索：内存矩阵暴力点积，只回传 id + 距离。1024 维 × 1 万条 ≈ 40MB、单查询 ~ms 级；到 5 万条 ≈ 200MB、~10ms，仍在舒适区。

### 3.3 R3 trigram

- 独立 FTS5 虚表，可单独开关；**不作为"低权重信号"**（RRF 没有权重机制，见 §4）。
- 文档与 UI 必须注明：1–2 字查询在此路不可用。

### 3.4 R4 图邻居（FalkorDB，默认关）

- 只做实体 1 跳邻居；不承接全文/向量（FalkorDB 全文无中文分词、HNSW 不能与属性过滤结合、SSPLv1）。
- 实体抽取异步，失败不阻塞写入（`derive_state` 的 `graph` stage）。

### 3.5 R5 纠正后补（事件驱动，非常驻池）

**不做**：`SELECT from_id FROM supersedes LIMIT 50` 平铺进候选池——那等于给 RRF 加一组无查询相关性的底噪，复刻 R4 被证伪的病。

**做**：融合流程里的一个**补救步骤**——某条候选记录因被作废而在输出前被剔除时，沿 `supersedes` 边把**它的纠正者**（指向它的 supersede 边的 from_id）拉进输出，继承被剔除项的位置。

- 仅对被剔除的候选生效，不参与 RRF 打分，不占常规名额。
- 纠正者自身也要过作废过滤（可被再纠正 → 沿链条继续追，最多 3 跳，超过则丢弃并计数）。
- 多条纠正者并存（B1、B2 都纠正 A）：**全部保留**，符合"不判断哪条作数"，由提示词契约让读者看到并存并追问；此行为写进测试。
- 保留条数上限与"追链超限"都必须计数可见。

### 3.6 R6 最近 50 条（兜底）

- 仅当前几路去重后 < 6 条时启用：`ORDER BY recorded_at DESC LIMIT 50`。
- 不做常规召回参与（依据见 1.1，属低风险假设）。

## 4. 融合与裁剪

```
R1..R6（各自 top-50，各路 SQL 内排除作废记录）
   → 每路去重、定长截断（50，截断数落日志）
   → RRF(k=60)：score(d)=Σ 1/(60+rank_i)
   → 固定 tie-break：RRF 分相同 → recorded_at 新者优先 → id 字典序
   → 取 6 条（FINAL_K）
   → MMR（默认关；开启时 λ=0.7、迭代选样、RRF 分先 min-max 归一化）
   → 作废剔除 → R5 纠正后补（继承位置，不参与打分）
   → 会话邻域展开（同 session_id，±2 条；展开项**同样过作废过滤**）
   → 输出总量上限（24 条/约 12K 字符，超出截断并标注）
   → 截断自报（>1200 字符标「[已截断，原文 N 字，id=…]」）
```

硬性规则：

1. **作废过滤在各路 SQL 内部完成**（共享同一个 CTE/helper），不是融合后过滤。
2. **作废语义按 01 文档的 per-pair 最新边**：对每个 `(from_id,to_id)` 取 `recorded_at DESC, id DESC` 最新边，`kind='supersede'` 才作废、`revoke` 恢复。**禁止**天真的 `NOT IN (SELECT to_id WHERE kind='supersede')`（忽略 revoke、忽略同 pair 后来的 revoke）。
3. **每路先去重再截断**；同一 id 在一路内重复不重复计分。
4. **tie-break 写死**，两台机器结果可复现。
5. **MMR 默认关**，等真实 embedding 重测证明增益再开。
6. **会话展开在融合与 MMR 之后**：不占 6 条名额、继承父项名次、不重新打分、**必须过作废过滤**；重叠邻域按"父项名次 → recorded_at → id"确定性合并；总输出受上限约束。
7. RRF **不带权重**（无机制支撑）；若将来某路长期霸榜，先调 `ROUTE_TOP_K` 或关路，不引入权重。
8. **向量路故障必须降级而非失败**：embedding API 超时/报错时跳过 R1、其余路照常、计数并让 `/health` 暴露，不得让整个查询 500，也不得返回静默空结果。
9. **展开后总输出上限 12 条 / 12000 字符**（含本体 6 条），超出即截断并标注；上限比"6+24"低，因为读者 context 有限，展开项挤占会反噬。

## 5. 可观测性（防静默失败）

每次查询落一行结构化日志：各路原始条数、去重后条数、截断条数、融合后条数、作废剔除数、纠正后补数、会话展开数、最终条数、是否触发 R6 兜底、是否触发短语→OR 回退、耗时分解。

`/health` 增加：各路最近空结果率、未派生条数（已有）、备份状态（已有）、**生效配置快照**（模型名/维度/启用路线/开关）。

## 6. 验收标准

1. 出厂查询构造器在 119 条老语料上 R2 单路 R@6 ≥ **0.44**（= 0.4875 减去 0.05 噪声带宽；不写死等于点估计的 0.4875）。
2. 真实 embedding 就位后重跑 R1 与 MMR，用同一 harness，结论写回本文档。
3. **融合结果低于最好单路时自动降级**：默认路线自动收窄到 R2（+R5 补救），**不要求 owner 手工改配置**；降级本身落日志。
4. 每路可独立开关；关掉任一路不丢数据、不报错。
5. 作废过滤测试：被作废记录不得出现在任何一路前 50、也不得经会话展开复活；revoke 后恢复可被检索；同毫秒 revoke→supersede 有序。
6. 会话展开测试：邻居出现、不占名额、过作废过滤、总输出不超上限。
7. 中文 1 字、2 字查询必须命中（R2 专项，含标点/数字/Latin 混合用例）。
8. R5 测试：候选被剔除后其纠正者出现；纠正者被再纠正时追链；多纠正者并存全部保留；追链超 3 跳被丢弃且计数。
9. R6 测试：结果不足 6 条时兜底触发、足量时不触发。

## 7. 明确不做

- ANN 索引（FAISS/hnswlib/usearch/sqlite-vec）：万条级 numpy 暴力毫秒级、40MB。
- FalkorDB 承接全文/向量。
- Graphiti 的 k=1 RRF、一次性 MMR。
- RRF 加权（无机制支撑）。
- 写入时 LLM 判断、冲突检测、学习排序、cross-encoder 重排（观察项）。
- 分词扩展 `simple`（新增 DLL 运维面；二元组精度不够再评估）。

## 8. 配置与模型管理（一切模型可换）

原则：**跑什么是配置的事，代码只认接口**。

| 配置项 | 说明 | 默认 |
|---|---|---|
| `EMBEDDING_BACKEND` | `openai-compat` / `local-onnx` | `openai-compat` |
| `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` | OpenAI 兼容端点与密钥（走 .env） | 空 |
| `EMBEDDING_MODEL` | 模型名 | 空，**启动时必填校验** |
| `EMBEDDING_DIM` | 维度；`auto` = 首次调用推断并落 meta 表并校验 | `auto`（维护者常用模型为 1024 维，但不由代码写死） |
| `LLM_BASE_URL` / `LLM_API_KEY` | 回答模型端点 | 空 |
| `LLM_MODEL` | 回答模型 | `deepseek-flash` |
| `LLM_MAX_TOKENS` | 生成上限（DeepSeek reasoning 会吃预算，给少会返回空串） | `3000` |
| `RETRIEVAL_ROUTES` | 启用路（语义名，避免编号错位），逗号分隔 | `vector,bigram` |
| `MMR_ENABLED` / `MMR_LAMBDA` | MMR 开关与 λ | `false` / `0.7` |
| `RRF_K` / `ROUTE_TOP_K` / `FINAL_K` | 融合常数 / 每路深度 / 最终条数 | `60` / `50` / `6` |
| `EXPAND_MAX_ITEMS` / `EXPAND_MAX_CHARS` | 展开后总输出上限（含本体） | `12` / `12000` |

硬规则：

1. **模型变更必须触发重建**，不允许新旧向量混存：`model_id + dim` 不符 → 拒绝检索 + 提示 `POST /admin/rebuild`，**不自动重建**（防静默花 API 钱）。
2. **密钥只走 `.env`**，仓库不含真实地址/密钥。
3. **换 LLM 只影响生成**，不需重建数据；换模型后要用同一套题库重跑（历史实测读者模型差异 95% vs 75%）。
4. **配置错误必须在启动时暴露**（如启用 R1 但模型名为空），不允许拖到查询时报错。

## 9. 风险

1. **规模外推**：所有"RRF 无增益"的结论来自 119 条；数千条必须重测。
2. **embedding 依赖**：API 形态引入外部端点依赖（网络/额度），本地形态引入 90MB 模型与冷启动。任一形态可整体关 R1 退化到 R2，不违反硬约束。API 失败必须显式报错并计数。
3. **子串级匹配的极限**：R2 对同义改写无效，真实 embedding 是唯一语义补位，两者都不能关。
4. **golden 口径**：题库标准集是"相关上下文"不是"答案集"；端到端问答评测要换口径。
5. **R5 追链**：3 跳上限是拍定的（无实测），超过即丢弃并计数；若真实使用中频繁触顶，说明纠正链模型需要重新设计。
6. **繁简**：NFKC 不做繁简转换，简体查询打不到繁体原文 = 静默 0 命中。属已知静默路径，低成本缓解（影子列同时索引简转繁 bigram）留作观察项，不引入新依赖。
7. **ANN 的回头路**：暴力扫描在万条级（40MB/ms）到 5 万条（200MB/~10ms）都成立；**≥5 万条或常驻内存 >300MB 时重议 ANN**，这是明确的触发条件。
8. **展开上限 12 条**：比理论最坏值（30 条）保守，因读者 context 有限；若真实使用中频繁触顶，再评估。
