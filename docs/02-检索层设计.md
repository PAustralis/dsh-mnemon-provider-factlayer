## 0. 一句话

**事实层不动。检索层只保留有证据的路线：一条与实测基线同构的二元组路（出厂唯一开启），被作废的记录由存活纠正者在路内顶替，排除只发生在出口。出厂默认即可用、可复现、零外部依赖。**

## 1. 实测基线

语料 119 条 / 题库 40 题；随机基线 R@6 = 0.0505。

| 路 | R@6 | R@10 | MRR | 覆盖@50 | 空结果 |
|---|---|---|---|---|---|
| R2 二元组（单列） | **0.4875** | 0.5000 | 0.6269 | 0.5000 | 2/40 |
| R1 向量（TF-IDF 替身） | 0.4583 | **0.5333** | 0.6051 | **0.6667** | 0 |
| trigram（不实现） | 0.1750 | 0.1750 | 0.3083 | 0.1750 | 24/40 |
| 最近 50（不作路） | 0.0667 | 0.1062 | 0.0974 | 0.4479 | 0 |
| unicode61（已废） | 0.0000 | 0 | 0 | 0 | 39/40 |

结论：31 种融合无一超过最好单路；RRF 收益 CI 跨 0；最近路显著有害；MMR 增益 0；唯一正向 MRR +0.008。

**局限**：向量路是替身；119 条规模小（80 个候选位，0.01 容差 ≈ 一条不能翻）；golden 是相关记录非答案集。

## 3. 基线同构的索引规格（B2/B3 + N6/N8）

### 3.1 出厂索引：单混合列，逐字复刻基线

`research/recall/recall_eval.py::bigrams_of` 就是规格（已核对源码）：

```
对 content 做 NFKC
按码点切段：CJK 连续段 / Latin+数字连续段 / 其他（标点空白）
CJK 段：len == 1 → 产出该单字；len > 1 → 产出该段全部双字（不产单字）
Latin 段：整段小写，作为一个 token
全部 token 空格连接，写入【同一个】bg 列，一个 FTS5(unicode61) 索引
```

- **不拆两列**：拆列会改变 BM25 的 IDF 与文档长度归一，排序不再等价，"逐字节复刻"失去意义（B2）。
- "单字+双字"的早期设计作废：基线只在 CJK 段长度恰为 1 时产单字；这也是 2/40 空结果的来源。
- 分词函数必须是全函数：非法代理对、超长文本不抛异常（派生失败=写入失败）；`content` 设长度上限，超限在写入层显式拒绝。
- 写入即索引：ngram 派生与事实写入同一事务，不允许"写进去了搜不到"。

### 3.2 查询构造与复刻验收（N6）

- 主路径逐字复刻 `bigrams_of(content)` 的查询侧：同一函数、同一分段、CJK 双字 OR（孤立单字段产单字）、Latin 整词；转义双引号，禁用 NEAR/AND/NOT/`*`。
- **Golden fixture**：`research/recall` 一次性生成 fixture（每题基线查询串 + 预期 top-6 + sha256 + 基线 commit），提交进产品仓库；产品测试用自己的构造器重算并断言逐字节相等，运行时不依赖 research 代码。
- 转义若改字节：分别存档"转义前 token 序列"与"转义后最终串"两份黄金文件，并对基线语料断言转义恒等。
- 空查询保护：token 数 0（极端输入）→ 直接 NO_MATCH，不构造空 MATCH 表达式。
- 查询 token 上限 200，截断计数。

## 4. 作废与纠正（B1 + B4 + B5 + N1/N2）

### 4.1 唯一最终集合 hidden（B5）

同一只读事务内计算：

- `voided_initial`：per-pair 最新边（`ORDER BY id DESC`，`supersedes.id` 为 AUTOINCREMENT）为 supersede 的 to_id。
- `cycle_pardoned`：处于环中、无存活纠正者的成员（递归 CTE + UNION 去重自带环保护）。
- **`hidden = voided_initial − cycle_pardoned`**，这是**全系统唯一口径**：路内替换、出口断言、"另有 N 条"计数、日志、`/health` 全部只用它。环成员不出现在 hidden 里（否则会被隐藏且替换目标为空 = 静默丢数据）。

### 4.2 各路检索**不**排除（B1）

各路取**含 hidden 的**原始 top-K。SQL 层不得排除；`hidden` 只用于：路内替换、出口断言、被隐藏匹配计数。向量路先取 top-K 再替换，不预先 mask。

### 4.3 路内替换（RRF 之前）

```
每路取原始 top-K（含 hidden 成员）
  → 命中 A ∈ hidden：用 live_head(A) 占据 A 的原始名次，A 移出该路列表
  → 路内去重：同 id 取最佳名次，每路每 id 至多一票
  → 按（名次 asc, seq desc）确定性排序 → 截断 50
  → 进 RRF
```

- 跨路各得一票是正当多路证据；同路绝不重复计票。
- 被作废项只当"位置提供者"，不进 RRF、不参与打分；替换后不重排名次。
- 多个存活纠正者并列继承 A 的名次；输出按 seq 新→旧，标「取代 id=A」。
- 因取代入选（文本不含查询词）也打标签，防误解为自身匹配。
- FINAL_K=6 是替换后的 6，纠正者占名额。

### 4.4 环（B4）

- **写入时拒绝成环**：新边若在 (from→to) 图产生环（含自环），同一写事务内检测，返回 409「该裁决会形成循环，已拒绝」，原文错误只进日志。
- **读路径防御**（历史数据）：环整体在 RRF 只算一票（环内最佳名次）；**12 条输出上限优先**——正文最多展示 3 个最新成员，其余**完整列出 id 清单**并注明可用"按 id 取全文"接口取回（01 已有）；全部标「循环裁决」。
- 链：安全阀 20 跳，触顶输出已到达节点并标注，不丢弃。

### 4.5 出口断言

最终输出若含 `hidden` 成员且不属于豁免（`include_superseded=true` 的显式请求）→ 丢弃、计数、ERROR 日志（带 query id 便于复现）、测试失败。丢弃是设计内行为，不算静默丢；但触发即说明替换逻辑有 bug。

## 5. 融合与输出

```
快照(hidden, live_head)
  → 每路：top-50（含 hidden）→ 路内替换 → 去重 → 排序 → 截断
  → RRF(k=60) → 同分 seq 大者优先 → 取 6
  → [会话展开：默认关，开启时过替换语义、不占名额、继承名次]
  → 输出上限 12 条 / 12000 字符（溢出列 id 与数量）
  → 截断自报（>1200 字符标「[已截断，原文 N 字，id=…]」）
  → 出口断言
```

### 5.1 输出语义

- **NO_MATCH**：显式状态 + 路状态摘要（参与路、降级路、token 数），绝不"多路皆空却返回空列表"。
- **弱匹配**：低分结果标 `weak:true`。
- **被隐藏匹配计数**：「另有 N 条与你相关、已被纠正，未显示」——N 只计"被替换而未出现在输出"的记录。
- **最近分区**：无命中时可选「最近记录（与查询无关）」，明确标注，不混入主结果。
- **include_superseded**：显式请求时返回历史说法，带状态标记。
- **展开/截断**：列出被丢弃 id 与数量。

## 6. 排序与单调序（B3）

- `memories` 增加 **`seq INTEGER PRIMARY KEY AUTOINCREMENT`**（`id TEXT` 保留为对外标识，改 `UNIQUE NOT NULL`）。理由：隐式 rowid 会被 `VACUUM INTO` 重编号、删除最大行后复用——而我们的备份正是 VACUUM INTO。
- 迁移：无生产数据，建表即新结构，附 `migrate_memories_seq()`（旧库重建回填）；README 注明。
- tie-break：**seq DESC**；不采信客户端时钟。
- `supersedes` 最新边：**只按 `id DESC`**，不依赖 recorded_at（时钟回拨会选错边）。

## 7. R1 向量路（默认关；B7 + N4）

- 模型可配置：`EMBEDDING_BACKEND=openai-compat|local-onnx`；`EMBEDDING_MODEL` 必填、启动校验；`EMBEDDING_DIM=auto`（首次调用推断落 meta 表，之后校验）。
- **内存矩阵一致性（B7）**：写事务提交后**增量刷新**内存矩阵（新增/替换该行向量），无 embedding 行的记录同时被排除在 R1 候选之外；矩阵与 DB 用 seq 对齐并定期校验。启动时全量载入。
- 后端单点计算，客户端只发文本；按行存 `model_id + dim`。
- 模型变更：后台重算（断点续跑、限速、预估总量），超 `EMBEDDING_MAX_SPEND_USD`（默认 0.50）暂停并告警，人话措辞：「向量重建已暂停：已完成 1200/1900 条，已花 $0.50（上限）。回复"继续"可追加预算。」同一告警每会话一次，`/health` 存完整版。
- 维度不符但模型未变 → R1 关闭 + 告警，不自动重建。
- 故障降级：单次 3 秒超时、连续 3 次失败熔断 5 分钟；**告警写入 provider 返回内容**（「⚠ 向量路不可用，本次仅文字匹配」）。

## 9. 验收标准

1. **基线精确再现**：产品构造器对全部 fixture 查询串逐字节相等；R@6 = 0.4875（容差 ≤0.01，即一条不能翻）。确认 seq tie-break 不翻转基线结果；翻转则查因，不放宽容差。
2. **变体门槛**：任何对基线构造的改动（单字兜底、uni/bi 两列、两列合并策略）都必须单独跑基准 ≥0.4875 才允许出厂；共用同一 harness 与门槛，禁止变体套变体。
3. **R1 开关门槛**：真实 embedding 重测后 R@6 +0.05 且 bootstrap 95% CI 不含 0，才进默认。
4. **作废一致性**：性质测试——输出 ∩ hidden ⊆ 豁免集；环成员不在 hidden；revoke 恢复可检索；同毫秒 revoke→supersede 以 id 有序。
5. **路内替换**：A 被作废且命中 → 纠正者占 A 名次、不超额；A 被两路命中 → 纠正者两票；同路不重复计票；多纠正者并列；"因取代入选"标签存在。
6. **环**：写入成环 409（含自环）；历史环只算一票、正文最多 3 个、其余列 id、标注存在；12 条上限优先。
7. **seq**：`VACUUM INTO` 后 seq 不变；迁移回填正确；tie-break 可复现。
8. **无命中语义**：全路空 → NO_MATCH + 路状态；隐藏匹配计数正确；`include_superseded` 可用。
9. **中文查询**：1 字、2 字、标点、数字、Latin 混合；FTS5 语法字符不报错不改义；超长截断计数；空 token → NO_MATCH。
10. **写入即索引**：写入成功立即可检索。
11. **重建**：整个重建在一个写事务内（数据量小）；查询始终看到完整旧/新索引；期间写入不丢。
12. **金丝雀**：用与产品一致的 NFKC+分段构造器抽子串（单 CJK 段 ≥6 字，不跨标点），N=20，连续两次失败率 ≥20% 告警；只对 bigram 路严格断言；标 canary 不计统计；失败记录 id。

## 10. 推迟项

- 单字兜底 / uni-bi 两列：按 §9.2 变体轨道，证明后再议。

## 12. 明确不做

ANN、FalkorDB 承接全文/向量、Graphiti k=1 RRF/一次性 MMR、RRF 加权、学习排序、cross-encoder 重排、分词扩展 `simple`、写入时 LLM 判断、冲突检测、软删除、运行时质量自动降级、把"拒绝检索"当模型不匹配响应。

## 13. 风险

1. 规模外推：融合无增益结论来自 119 条，数千条必须重测（发布时离线）。
2. 单路出厂：默认只有 bigram，同义改写查不到；配置 R1 并重测是必要动作。
3. 子串极限：bigram 对同义改写无效。
4. golden 口径：标准集是相关上下文，端到端评测要换口径。
5. 语料外发：R1 API 形态会把原文发给第三方 embedding 服务；local-onnx 可避免但需 90MB 冷启动，README 必须写明。
6. 环：写入拒绝后以 409 暴露，UI 文案需解释"这两条不能互相作废"。
7. 繁简：不转换 = 静默 0 命中，用 /health 繁体占比可观测。
8. 变体轨道：任何"更好的分词/更多列"都要过同一门槛，否则容易凭直觉上复杂方案。
