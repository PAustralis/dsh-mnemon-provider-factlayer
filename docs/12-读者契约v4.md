# 12 · 读者契约 v4（定稿）

> 依据：`docs/11-契约对读者级的影响.md`（A–E 五组对照，共 400 次真实调用；全部缓存可复现）。
> 状态：**定稿**，作为"读者如何读记忆"的规范；改动必须重跑同一套对照。

## 1. 为什么需要契约

检索已经不是瓶颈：证据级 R@4 ≈ 0.97、R@20 = 1.0，34/36 题的证据全在前 4 条。
瓶颈在**读者怎么处理多条记录**——尤其"说法冲突"和"没有日期"。

实测（40 题，可答 36）：

| 组 | 契约 | ✅ | ❌ | 合格率 | 可答题正确率 |
|---|---|---:|---:|---:|---:|
| A | 题库原说明（无契约） | 26 | 11 | 72.5% | 61.1% |
| B | v2 | 19 | 1 | 97.5% | 41.7% |
| C | v2 + 日期前缀 | 20 | 0 | 100% | 44.4% |
| D | v3 | 28 | 7 | 82.5% | 66.7% |
| **E** | **v4** | **26** | **2** | **95.0%** | **61.1%** |

- v2 把"自信答错"几乎清零，但把 7 道本该答对的题变成"反问"——它没有区分"会变的属性"和"稳定事实"。
- v3 修好了那 7 题（A→D：4 好 0 坏），但"以最新为准"边界过宽，同日冲突/跨场景记录被强行排序，❌ 回到 7。
- v4 加了三条硬规则（同日不可排序、稳定事实永不挑边、无日期≠更旧 + 计数题规则），**同时压住两头**：✅ 不低于基线、❌ 从 11 降到 2。

## 2. 契约全文（v4，逐字）

```
回答这些关于我本人记忆的问题时，请遵守：
1. 直接给出答案；如果答案来自记忆，说明依据的是哪一天记的那条。
2. 如果多条记录对同一件事给了不同的说法，按下面处理：
   a. 只有当两条记录的日期不同、并且较晚的那条明确写明了发生了改变
      （换了、改成、调到、搬到、减到、换成、不再 等），才以较晚的那条为准直接回答，
      并说明"按 X 年 X 月 X 日的记录"；旧说法最多用一句话带过。
   b. 如果日期相同、或者较晚的记录没有明确说明发生了改变（只是补记、换个说法），
      就认为无法确定哪条对，把每种说法和日期列出来，然后问我。
   c. 不会随时间变化的事实（血型、过敏、出生年份、药量、宠物的年龄）永远按 b 处理，
      即使日期不同也不要自己挑一条。
   例外：如果其中某条是「已确认」「已作废」这种我本人裁决过的结论，以那条为准直接回答。
3. 如果记忆里根本没有答案，直接说没有，不要编。
4. 如果所有记录说法一致，直接回答，不要把同一件事换个说法重复一遍。
5. 如果有关记录没有日期，说明"这条没记时间"，给出更可能的那一条作为倾向，
   但不要把"有日期"当成"更晚"或"更可信"的理由。
6. 如果问题是"几次/多少个"这类计数，只数同一次事件时间线上的记录；
   同一件事的补记不算新增。
```

## 3. 剩余误差（不是契约能修的）

v4 剩 2 道 ❌（场景 3 换工作次数、场景 11 公司）与 1 道退步，全部因为 **top-4 混进了别的场景的记录**：

- 记录本身**没有场景/时间线标签**，契约只能靠日期判断，而跨场景记录恰好日期更晚
- 修它要动检索层：给记录加"场景/时间线"元数据，或在 top-4 里做同主题去重

## 4. 交付方式

契约必须进入**读者模型的系统提示**才生效。provider 只能返回检索结果，无法注入提示词。可选通道：

| 通道 | 做法 | 可靠性 | 代价 |
|---|---|---|---|
| **A. persona（推荐）** | profile 的 `cordis.patch.yml` 按条目 id 覆盖 `persona` 的 `config.prefix`，在原文后追加契约 | 每轮生效 | 改 profile，需重启；一条 patch，易回滚 |
| B. skill | 写进 `~/.dsh/skills/`，靠模型按需加载 | 不保证加载 | 零风险 |
| C. 结果内容 | provider 把精简契约附在结果里 | 可控但污染证据 | 不推荐 |

**排序**：先 A（可靠），B 可作为补充（描述里写"回答关于记忆的问题前先加载"）。

### 4.1 persona 补丁样例

```yaml
# 追加契约到系统提示；必须保留原有 prefix 原文与 {{model}} 模板
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: |
      You are a coding agent powered by the {{model}} model.
      <v4 契约全文>
```

- 改前备份 `cordis.patch.yml`；改后重启后端；回滚＝删掉该条目再重启。
- 验证：开一个新会话，问"我车位在哪"（该题有换车位记录），看是否按最新日期答；再问一个血型类问题，看是否列出两种说法并反问。

## 5. 维护规则

1. 契约变更 = 契约版本号 +1，并重跑 A–E 对照；不重跑的改动不算数。
2. 单条规则的效果必须有配对数据支撑（这次 v2→v3→v4 的每一步都有）。
3. 契约只约束"怎么读"，不改写入路径、不改检索排序。
4. 新增规则前先问：它修的是"读者行为"还是"检索/元数据"？后者不该写进契约（这次 2 道剩余 ❌ 就是例子）。
