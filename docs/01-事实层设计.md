# 事实层设计（第一层，定稿 v7 + 评审修订）

> 主轴：**派生层出错删掉重跑，事实层永远不动。**

本仓库是 dsh-mnemon 的记忆 provider 后端：一个 FastAPI shim，对上暴露 mnemon provider 的 HTTP 契约（remember / recall / forget 等，接口文档后续单独一版），对内采用双层存储：

- **事实层** = SQLite 单文件，只追加（INSERT only，事实表永不 UPDATE / DELETE）
- **派生层** = SQLite 内 embeddings 表 + FTS5 索引（随时删光重算零损失）；`entity` / `graph` 两个 stage 目前是 **stub**，FalkorDB **未接入**（`DSH_FALKORDB_URL` 只是配置项，代码里没有任何调用点）

存储引擎可换，对外接口稳定。

## 硬约束（一票否决）

1. 零人工维护——需要 owner 手动整理 / 纠正 / 确认的设计自动否决
2. 绝不静默丢数据
3. 单个非程序员维护者、最少活动部件
4. 写入时不判断「哪条作数」——无冲突检测、无相似度去重、无状态机

## 总体架构

主轴：派生层出错删掉重跑，事实层永远不动。

- 事实层 = SQLite 单文件，只追加（INSERT only，事实表永不 UPDATE / DELETE）
- 派生层 = SQLite 内 embeddings 表 + FTS5 索引，随时删光重算零损失；`entity` / `graph` 为 stub，FalkorDB 未接入（见「派生层」一节）
- 检索层（第二层，**以 `02-检索层设计.md` 为准**）：2026-11-11 真实 embedding 重测后出厂默认向量单路（R@6=0.8729），二元组仅在向量不可用时降级；MMR/图邻居/最近路/trigram 均未实现或默认关闭，作废与纠正改为「路内替换」。各路可独立开关，关掉不丢数据。

## 表结构（SQLite）

```sql
-- 事实表：只追加，永不 UPDATE/DELETE
CREATE TABLE memories (
  gseq         INTEGER PRIMARY KEY AUTOINCREMENT, -- 全局单调序（rowid 别名，VACUUM 后不变）
  id           TEXT UNIQUE NOT NULL,     -- 服务端生成的对外稳定标识
  client_write_id TEXT NOT NULL UNIQUE,   -- 客户端生成的 UUID，重试时原样复用（幂等键）
  content      TEXT NOT NULL,             -- 原文逐字全文，永不截断
  recorded_at  INTEGER NOT NULL,          -- 服务端 Unix 毫秒，唯一权威时间
  session_id   TEXT NOT NULL,
  seq          INTEGER NOT NULL,          -- 服务端在写事务内分配：BEGIN IMMEDIATE 内 SELECT COALESCE(MAX(seq),-1)+1 WHERE session_id=?（语义不变）
  event_time   TEXT,                      -- 用户自报，可空；按精度存 2026 / 2026-11 / 2026-11-11
  event_time_precision TEXT CHECK (event_time_precision IN ('year','month','day','instant')),
  source_client TEXT NOT NULL,            -- 客户端标识
  CHECK ((event_time IS NULL) = (event_time_precision IS NULL))
);
CREATE INDEX idx_memories_session ON memories(session_id, seq);
CREATE INDEX idx_memories_time ON memories(recorded_at DESC);

-- 作废边：用户裁决的机械记录，非机器判断；撤销作废也走追加
CREATE TABLE supersedes (
  id         INTEGER PRIMARY KEY AUTOINCREMENT, -- 追加顺序，最新边的唯一 tie-break
  from_id    TEXT NOT NULL,               -- 裁决记录 id
  to_id      TEXT NOT NULL,               -- 被作用记录 id
  kind       TEXT NOT NULL CHECK (kind IN ('supersede','revoke')),
  reason     TEXT,
  recorded_at INTEGER NOT NULL,
  source_client TEXT NOT NULL
);
CREATE INDEX idx_supersedes_pair ON supersedes(from_id, to_id, id DESC);
CREATE INDEX idx_supersedes_to ON supersedes(to_id, id DESC);
-- 某条是否作废 = 对每个 (from_id,to_id) 分别取 ORDER BY id DESC 的最新边；
-- 任一最新边为 supersede → 作废，全部为 revoke 或无边 → 未作废。
-- 逐 pair 语义：B 的 revoke 只作用于 (B,A)，不能撤销 A 的 supersede。
-- （早期实现用 (from_id,to_id,recorded_at) 当主键，同毫秒 revoke 后再 supersede 会撞 PK，
--  故改为自增 id 主键；旧库在 init_db() 时自动重建该表，见 README。）
-- 最新边只按 id DESC，不依赖 recorded_at（时钟回拨会选错边）。

-- 派生侧（全部可弃）
CREATE TABLE derive_state (
  memory_id TEXT NOT NULL,
  stage     TEXT NOT NULL CHECK (stage IN ('fts','embedding','entity','graph')),
  done_at   INTEGER NOT NULL,
  PRIMARY KEY (memory_id, stage)
);  -- 水位表：后台循环 SELECT 未完成条目 ORDER BY gseq LIMIT 50 逐条补；重放与全量重建走同一条代码路径
CREATE TABLE embeddings (
  memory_id TEXT PRIMARY KEY,
  vector    BLOB NOT NULL,                 -- float32，维度由 EMBEDDING_MODEL 决定（默认 auto 推断），启动载入内存做 numpy 暴力点积
  model_id  TEXT NOT NULL DEFAULT '',      -- v8：按行记录生成模型，模型变更时拒绝混存
  dim       INTEGER NOT NULL DEFAULT 0     -- v8：按行记录维度
);
CREATE TABLE entities (
  memory_id TEXT NOT NULL,
  entity    TEXT NOT NULL,
  PRIMARY KEY (memory_id, entity)
);
CREATE INDEX idx_entities ON entities(entity);
-- FTS5 虚表建在 memories.content 上（触发器同步，可弃可重建）
```

## 写入层（零判断，只有机械动作）

1. 原文逐字全文入库，不解析 / 不改写 / 不去重 / 不截断
2. 服务端时间戳（毫秒）；会话内排序以 seq 为准，recorded_at 仅参考（防时钟回拨）
3. seq、id 均由服务端分配；客户端只提供 client_write_id
4. 幂等：client_write_id 为 UNIQUE。重试同 id：
   - 内容一致 → 返回已有记录（写回执：id、seq、recorded_at）
   - 内容不一致 → 显式 409 报错，绝不静默 IGNORE
   - 幂等键不参与任何内容哈希（前缀哈希会撞号静默丢，已否决）
5. 用户真的重复说同一句话 = 两个不同 client_write_id = 两条都存；重复信号不靠字段，靠多条记录本身，检索统计放派生层
6. 写入回执：客户端收到 `{id, seq, recorded_at}` 才算成功；没回执必须本地暂存并用同一 client_write_id 重试（客户端规范，断网时防静默丢）
7. 客户端规范（写入侧）：本地未确认队列 + 同 id 重试

## 读取 / 输出规范

- 单条超 1200 字符只在**读取注入上下文时**截断，并标注「[已截断，原文 N 字，id=…]」，同时提供按 id 取全文的接口；入库永远是全文

## 派生层

- 后台循环按 derive_state 水位补 `fts`（ngram/bigram/trigram）和 `embedding`；失败不阻塞写入
- **`entity` / `graph` 是 stub**（`app/derive.py` 里恒成功、不做事），**FalkorDB 未接入**：`DSH_FALKORDB_URL` 只被读进 config（`app/config.py`），仓库内无任何使用点；`graph` 检索路线显式「本层未实现」，调用即返回空并计入 `/health`（`app/retrieval.py` 的 `graph_route`）。FalkorDB 图数据库是**设计目标，未实现**
- embedding 失败 = 条目停留在未完成状态并计入失败计数，绝不静默跳过
- /health 暴露：各 stage 未派生条数、失败计数、备份最后成功时间
- 全量重建 = 清空 derive_state + embeddings + ngram/FTS 派生表，循环自动补齐

## 运维

- `PRAGMA journal_mode=WAL; synchronous=FULL; busy_timeout=5000; foreign_keys=ON`
- 所有写走单写连接（asyncio.Lock 或专用线程）；部署固定单 worker
- 备份：每日自动 `VACUUM INTO 'backup-YYYYMMDD.db'`（WAL 下直接拷 .db 会漏 -wal 数据），保留最近 N 份 + 异地一份；备份是硬需求不是优化项。自动备份由后台线程按 `DSH_BACKUP_INTERVAL_SECONDS`（默认 86400，0 关闭）检查 `last_backup_at`，失败写服务端日志并在 `/health` 暴露 `last_backup_error` + 连续失败计数。写入用「临时文件 + `os.replace`」保证同日重跑不出现零备份窗口。
- SQLite 后台维护与派生/备份**共用同一个后台线程**：`DSH_DERIVE_LOOP_ENABLED`、`DSH_BACKUP_INTERVAL_SECONDS`、`DSH_WAL_CHECKPOINT_INTERVAL_SECONDS`、`DSH_FTS_OPTIMIZE_INTERVAL_SECONDS` 任一开启即启动；全部关闭时启动日志明确写「维护线程未启动」，`/health.maintenance` 直接给出 `loop_enabled` 与两项维护的启用状态。无写入空闲时执行 WAL `TRUNCATE` 检查点、按间隔执行 FTS5 optimize。
- 「距上次写入空闲 > N 秒」是**进程本地**判定：基准是进程内最后一次成功 COMMIT 的单调时钟。进程重启后内存时间戳清零，视为「从未写入」（即已空闲），不会沿用库文件或墙钟上的历史写入时间；优化间隔同样只用单调时钟，墙钟回拨/校时不会让维护停摆或提前。
- 所有配置走环境变量（见 `.env.example`），仓库不含任何真实地址 / 密钥
- 启动用工厂：`uvicorn app.main:create_app --factory --workers 1`；`import app.main` 不建库、不产生 facts.db
