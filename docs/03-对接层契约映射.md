### 1.2 请求：`SearchRequest`

> **HANDOFF §15.3 只给了签名 `search(body, request: SearchRequest, signal?)`，没有列字段**——这是本文必须补齐的第一个缺口。[A+] 依据：`P\types\contracts.d.ts:286-301`。

| 字段 | 类型 | 必填 | 契约语义 / 运行实况 | 证据 |
|---|---|---|---|---|
| `query` | `string` | **必填** | 自由文本，≤2000 字符（路由层 `required`、service 层 `required(…,"query",2000)`） | [A] §15.3；[A+] P:2397 |
| `mode` | `'smart'\|'keyword'\|'basic'` | 可选（缺省 `smart`） | Host 归一化后一定传三者之一；`smart` 可能触发 Host 自动补查（换 query 再调一次 search） | [A+] P:2404-2408、P:2450、P:2478-2500 |
| `limit` | `number` | 可选 | **语义不是"最终条数"，是候选量**：`candidateLimit = min(50, max(limit, ceil(limit×3)))`，默认请求 10 → Provider 收到 **30** | [A] §5（≤50）；[A+] P:1460-1462、P:3454 |
| `category` | `Category` 枚举（6 值） | 可选 | 白名单校验，非法直接抛错 | [A+] P:2409、`contracts.d.ts:242` |
| `source` | `'user'\|'agent'\|'external'` | 可选 | 同上 | [A+] P:2410 |
| `intent` | `'WHY'\|'WHEN'\|'ENTITY'\|'GENERAL'` | 可选 | 同上（Host 未做推断，纯透传） | [A+] P:2411 |
| `memoryBodyIds` | `string[]` | 可选 | **在 service 层被消费掉**，不进入 Provider 的 request（Provider 只拿到自己的 body） | [A+] P:2412、P:2413-2421 |
| `inspect` | `boolean` | 可选 | 只由 Host 置位（GUI 检视/内部读），表示"看而不是用"；Provider 可据此不计访问 | [A+] P:2420；`contracts.d.ts:294-300` |

**结论 1：请求侧没有扩展位。** 三个白名单（路由 schema → route 参数抽取 → service 重建）逐层只认上面 8 个键，**任何自定义参数都进不到 Provider**。[A+] 这是 [A] §7 坑 1（`RememberRequest` 无扩展位）在检索侧的同类事实，但 HANDOFF 未写出，属本次补齐。

## 4. 降级方案与"静默误导"判定

### 4.1 硬约束：**状态与结果不可兼得**

`P:4110` 是这次映射最关键的一行：**provider 的 `hint` 只在 `results.length === 0` 时才被转成 `evidence.unavailable`；一旦有结果，hint 在路由层就被丢弃——不仅模型看不到，连 UI 的读源面板也拿不到。**

推论（必须写进设计）：

1. `NO_MATCH` + 路状态摘要 = 天然兼容（就是空结果场景）。
2. **"最近分区"与 `NO_MATCH` 互斥**：返回最近项 → 结果非空 → 状态丢失 → 变成"有结果但没说是兜底"。02 §5.1 把两者并列，是契约上不可能的。
3. **"被隐藏匹配计数"在主结果非空时无状态通道**，只能寄生在 `content`/`tags`。
4. `weak` 同理。

### 4.2 各语义的推荐降级（按"改动最小 + 不撒谎"排序）

| 语义 | 推荐做法 | 明确丢弃什么 | 会不会静默误导 |
|---|---|---|---|
| `NO_MATCH` | `results: []`，`hint = "NO_MATCH｜routes=vector(unavailable:circuit_open)+bigram(ok)｜tokens=0｜hidden=0｜degraded=vector 不可用（circuit_open），已降级 bigram"` | 无 | 不会，但须接受它显示在 `unavailable` 键下（键名不准，文案补救） |
| 路状态摘要 | 并入上面 §1 的 hint 文案；**结果非空时不表达** | 非空场景下的路状态 | 会（弱）：模型不知道只有单路。缓解：`/health` 已有完整版（02 §7），模型侧不留 |
| 被隐藏匹配计数 | **拼进首条结果的 `content` 尾行**：`〔另有 2 条相关记录已被纠正，未显示〕` | 不做计数 = 丢 | **丢弃会静默误导** → 必须保留；`tags:["hidden:2"]` 作为冗余（模型可见、零正文成本） |
| `weak` | `tags:["weak"]`（首选）+ 不阻塞正常展示 | 丢 = 模型把弱匹配当强证据 | 丢弃会误导，tags 成本极低，必须保留 |
| 最近分区 | **不实现**（02 §5.1 的"可选"建议直接砍掉）；若要保留，只在 `NO_MATCH` 之外单独一次 admin 查询 | 完全丢弃 | 不误导，只是少一个兜底 |
| 来源路 / 展开项 / 因取代入选 | 统一前缀写进 `tags`（`via:bigram`、`expanded`、`superseded-by:<id>`），每条的 tag 上限 **8 个、每个 300 字符** | 超出 8 个的 tag 被截 | 截断后语义仍在（前 8 个优先放状态标记） |
| 分数细节 | 丢弃（不进模型） | RRF 分值本身 | 不误导：分数对模型无用，序已表达 |

### 4.3 为什么 "拼进 content" 不是脏做法

HANDOFF §23 已经为同一类问题定过案：`RememberRequest` 没有扩展位（§7 坑 1）→ 结构化信号只能编码进 `content`，并且**必须用显式、可判定的围栏块，不能用自然语言模板 + 正则**（§23.1）。读侧同理：`content` 是唯一有富余、且模型必读的通道。

差别：写侧用 ` ```fact ` 围栏块（§23.2），读侧建议用**单行短标记**（`〔…〕`），因为读侧每条只有 1200 字符且模型是"读一段话"而不是"解析一份文档"。若将来读侧标记要机读，应照 §23.5 的纪律**先剥离再进模型可见面**。

### 4.4 `tags` 做状态通道的两个已知风险

1. **写入侧 `tags` 值禁英文逗号**（§7 坑 1，含逗号直接抛错）；输出侧是否同样限制**未验证** → 一律不用逗号（用 `:` 或 `=`）。
2. `tags` 是 mnemon 自己的元数据字段（分类、`fact`/`invalid` 等，见 §24），塞状态标记会污染检索标签。对策：统一前缀白名单（`weak`、`via:`、`expanded`、`superseded-by:`、`hidden:`），并在 02 里声明"这些 tag 不参与写入语义"。

## 5. `include_superseded`：**不可达**

三层证据，任何一层都足以否决：

| 层 | 事实 | 证据 |
|---|---|---|
| 工具/路由 | `mnemon_recall` 的输入 schema `required:["query"], additionalProperties:false`，只有 `query/mode/limit/category/source/intent/memoryBodyIds` | [A+] `P:3757-3776` |
| service | 白名单重建 `normalizedRequest`，只保留 6 个键 + `inspect` | [A+] `P:2413-2421` |
| provider | 请求侧无扩展位（与 §7 坑 1 同构：白名单重建，多余键被丢弃） | [A] §7 坑 1；[A+] P:2413-2421 |

结论：**`include_superseded=true` 在模型路径上"不可达"**，不是"没实现"，也不是"Provider 可以选择忽略"——参数根本进不来，硬传会被 schema 拒。

替代（按推荐度）：

| 方案 | 做法 | 代价 | 判定 |
|---|---|---|---|
| **A. admin 端点（推荐）** | shim 自带 `GET/POST /admin/search?include_superseded=1`，用 02 §11 的 `ADMIN_TOKEN`（空则仅回环） | 零契约改动；模型不可见，只给人/测试/评测 | ✅ 推荐 |
| B. 第二个只读空间/实例 | 同库不同 group，专供历史查询 | 需多空间（§18/§24 的 group 限制）；运维成本高 | 备选 |
| C. query 前缀约定（`incsup:` 开头，Provider 剥离后检索） | 技术上可行 | 污染查询文本：进日志、进策略 query digest、影响 Host 自动补查；与"query 是自然语言"的工具描述冲突 | ⚠️ 不推荐，除非用户明确要求模型可自助 |
| D. 默认不返回 + 提示 | 默认口径就是"旧说法不返回"，纠正者已在结果里 | 无 | ✅ 与 02 §4 的默认语义天然一致 |

**连带结论：02 §5.1 的 `include_superseded` 要从"模型能力"降级为"运维/评测能力"，02 §9.8 的验收项"`include_superseded` 可用"必须改写为"admin 端点可用"。**

## 6. 契约逼着我们改设计的地方

| 优先级 | 02 现状 | 契约事实 | 必须改成 |
