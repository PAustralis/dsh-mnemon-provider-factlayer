# 15 · LongMemEval 试水成本（token / 延迟实测）

> 时间：2026-11-12。范围：**只测真实 token 成本与延迟**，5 题小样本、不做评测结论；没有改 `app/`、没有改 profile。
>
> 机读结果：[`research/bench/pilot_cost.json`](../research/bench/pilot_cost.json)；
> 调用缓存：[`research/bench/.llm_cache_pilot.json`](../research/bench/.llm_cache_pilot.json)（gitignore，10 条，复跑 0 调用）。
> 输入快照 `research/bench/converted/.pilot_snapshot.jsonl`（500 题 oracle 转换件）已在跑完后删除。
>
> **一句话：跑全量 500 题（1000 次调用）约 289 万 tokens、串行约 36 分钟（并发 4 约 9 分钟）、
> 约 $0.45（off-peak）到 $0.90（peak）；2000 次调用翻倍到约 578 万 tokens / $0.90–1.80。**

## 7. 局限与口径提醒

1. **5 题只够量级**：单题 token 随 facts 条数与轮长波动很大（1.1k–7.5k），全量 500 题的真实分布可能偏离本样本。
2. **样本 fact 规模偏小**：样本平均 18.8 facts/题，快照平均 21.9；reader prompt 大致随 facts 增长，全量可能比线性外推高约 10–20%。
3. **thinking 默认开**：completion 里含 reasoning tokens（本次 121/74/134/548/35），按输出单价计费；关掉 thinking 会显著降低 completion 成本，但本次按默认模式实测。
4. **cache hit 是服务端行为**：`prompt_cache_hit_tokens` 由 API 返回，按它计费；它和本地复跑缓存不是一回事。
5. **不产出评测结论**：judge 的 ✅ 仅用于验证链路与 prompt 结构。

## 8. 结论

跑全量 500 题（1000 次调用）约 **289 万 tokens、串行约 36 分钟（并发 4 约 9 分钟）、
$0.45–0.90（off-peak/peak）**；2000 次调用约 **578 万 tokens、$0.90–1.80**——
**成本不是瓶颈，时间也不是**（并发 4 下半小时内）。
