# 06 · 对接层设计（第三层）

> 依据：`docs/05-provider接口契约.md`（本机 dsh-mnemon@0.5.37 / source-memory-spaces@0.5.24 源码核实）、`docs/03-对接层契约映射.md`、`docs/02-检索层设计.md`（v8+）。
> 引用缩写：P = source-memory-spaces bundle，S = strategy 包，M = mnemon 主包（同 05 §0）。

## 0. 一句话

**第三层是一个极薄的 TypeScript 适配器包**：它实现 mnemon 的 `MemoryProviderAdapter`，把每个方法翻译成对我们 shim 的一次 HTTP 调用，并**在翻译时补齐契约要求的形状**（回执 action、ISO 时间、results 数组、scoreSemantics）。业务逻辑一律不在这层。

## 1. 交付形态（05 §1、§6）

- 产物：独立 npm 包 `dsh-mnemon-provider-factlayer`，导出 `MemorySpaceProviderManifest` 与 `create()`（provider 实例）。
- **GUI 安装器只认 `dsh-mnemon-source-*` / `dsh-mnemon-strategy-*`**（M:17131），所以本包落地方式 = **bundle patch / 手改 `cordis.patch.yml`**，README 写清步骤；不指望装进 GUI。
- 依赖：`dsh-mnemon` 的 `HttpMemoryProvider` 基类（05 §6.7）若可用则复用其 HTTP/超时/错误处理；不可用则自写最小 fetch 封装（15s 超时，对齐官方基类默认值）。

## 2. 能力声明（05 §6.3/§6.4）

```
capabilities: {
  search: true,
  remember: true,
  browse: false,        // list 只做最小实现，不当作浏览能力
  graph: false,         // 图邻居路未实现
  deletion: unsupported // 只追加，永不删
}
scoreSemantics: 'provider-native'   // manifest 与 adapter 两处都要写，且必须一致
writeMode: 'exact'
```

- `deletionMode: unsupported`：`forget` 不实现（可选方法），语义上"撤销"走纠正记录 + 作废边。
- `graph: false`：`graph()` 返回空快照（类型必填但能力位关闭，05 §2.1）。
- `discover` **必须实现**：保存服务配置时会被真实调用（05 §1/§7）。

## 3. 方法映射（05 §2/§3/§4）

| 契约方法 | shim 调用 | 适配要点 |
|---|---|---|
| `discover()` | `GET /spaces` | 返回单空间（配置里的 `memoryBodyId`）；重复调用幂等（不得重复挂载） |
| `status()` | `GET /health` | 映射成 `ProviderSpaceStatus`（healthy/degraded/unhealthy + 计数）；**漏实现会让空间永远 unhealthy**（运行时虽不校验） |
| `search(body, request)` | `POST /search` | 响应 `{items}` → **`{results}`**；每条 `recorded_at(ms)` → **`createdAt` ISO 8601 UTC**；保留 id/content/score/tags；`hint` 仅空结果时透传，且文案以 `NO_MATCH` 开头 |
| `remember(request)` | `POST /memories` | 见 §4（回执最坑） |
| `list(request)` | `GET /memories?session_id=` 或空 | 契约的 `MemoryListRequest` 无 session/offset；`browse:false` 下返回空或仅 query 命中；不伪造浏览能力 |
| `graph()` | 无 | 返回空 `MemoryGraphSnapshot`（能力位 false） |
| `get(id)` / `related` / `link` / `forget` / `rememberMany` / `entityIndex` / `metadataSample` / `invalidateStatus` / `dispose` | 不实现或最小实现 | 全部为可选；`dispose` 用来关连接池 |

## 4. 写入回执：契约里最阴的一处（05 §4.4、§7.3 W1）

**契约事实**：Source 用启发式判定 `committed`——`action:"stored"`（或 16 词之一）、`committed:true`、`durable:true`、或计数字段 > 0 任一命中即 committed；否则 `unknown`。而 `unknown` → 不触发空间激活 → 上游 `writeLanded` 为假 → 主 Agent 工具结果被改写成 `action:"unknown"`、`memoryBodyIds:[]`。**结果：记忆写了，模型被告知没写。**

**本层做法**：适配器把 shim 的 `{id, seq, recorded_at, client_write_id}` 翻译成契约形状：

```json
{ "action": "stored", "committed": true, "count": 1,
  "memoryBodyIds": ["<memoryBodyId>"],
  "ids": ["<memory id>"] }
```

- `action` 必写（16 词白名单内），同时给 `committed:true` 与 `count:1`（三保险，任一路径的判定都能命中）。
- 若 shim 返回"幂等命中"（duplicated:true）→ 仍返回 `action:"stored"`（写入确实存在），但 `count:0` 并把 `ids` 指向原记录，避免上游认为新增了一条。
- shim 真实失败（409/500/网络错误）→ **抛错**，让 RPC 变成 `internal`（05 §5.1：写路径全部直接冒泡，没有重试）。

## 5. 三个必填字段的来源（05 §7.3 W2/W3）

契约的 `RememberRequest` 没有 `session_id`/`client_write_id`/`source_client`，但事实层需要它们：

| 字段 | 取值 | 理由 |
|---|---|---|
| `source_client` | 固定 `"mnemon-provider"` | 标记来自适配器，不是本地脚本 |
| `session_id` | **`memoryBodyId`**（空间 id） | 契约没有会话概念；一个空间 = 一个"会话窗口"；会话展开因此粒度变粗，**默认关**（02 §10），可接受 |
| `client_write_id` | **每次调用生成 uuid4** | 契约无幂等位；用内容摘要会合并"真的写了两遍"（违反"绝不静默丢"）。上游无重试（05 §5.3），重复概率低；重复了看得见、可清理，**宁可重复也不吞** |

- 若将来上游加 retry：由适配器本地 outbox 负责（记录未确认写入 + 原 uuid 重试），仍然不引入内容摘要。

## 6. 检索结果的字段映射（05 §7.2）

| shim 字段 | 契约落点 | 处理 |
|---|---|---|
| `id` | `Insight.id` | 直传；缺失时**抛错**（契约的 TypeError 比静默丢更安全） |
| `content` | `Insight.content` | 直传（已按 1200 截断并带自报标记） |
| `recorded_at`（ms） | `Insight.createdAt` | **必须转 ISO 8601 UTC**；直接透传数字会被静默丢弃 |
| `score` | `Insight.score` | 保留数值 |
| `tags` | `Insight.tags` | 保留；确保无逗号、≤8 个、每个 ≤300 |
| `recorded_at`/`seq`/`session_id`/`routes`/`content_truncated`/`expanded*`/`inherited_rank` | — | **剥掉**，不进 Insight（策略层白名单也会丢，留着只是浪费 payload） |

## 7. 失败与降级（05 §5）

- 读路径：shim 5xx/超时 → 适配器抛错，Source 逐空间降级成 `unavailable` + hint（03 §4.1）。**不得返回空数组冒充"没有记忆"**。
- 写路径：抛错即可，不吞。
- 超时：适配器统一 15s（对齐官方基类默认）；shim 内部 R1 已有 3s 超时与熔断，两层不冲突。
- `hint`：只在 `results.length === 0` 时有意义；文案必须以 `NO_MATCH` 开头，避免模型把 `unavailable` 读成"服务故障"。

## 8. manifest 字段（05 §6.1）

必须逐项满足 16 个字段的校验；关键易错点：

- `apiVersion` 固定串（照抄同版本官方 provider）。
- `typeId` 必须**等于 module.id**（写错装配失败）。
- `secrets` 必须与 `fields` 里标记为 secret 的字段集合**完全一致**。
- `scoreSemantics` **两处声明**（manifest 三值 / adapter 两值）且必须一致；manifest 写 normalized 而 adapter 未声明 → 装配失败。
- `fields`：`baseUrl`（必填）、`apiKey`（secret，可空）、`memoryBodyId`（必填，空间标识）。

## 9. 端到端验收

1. `discover()` 连点两次"重新发现"不重复挂载（幂等）。
2. `remember` 一次 → 工具结果 `action` **不是** `unknown`；空间被激活（`status` 变 healthy）；`memoryBodyIds` 非空。
3. `search` 命中 → 结果进入模型上下文，`createdAt` 可读、分数不出现（契约正常行为）。
4. 空结果 → 模型看到 `unavailable` 且文案以 `NO_MATCH` 开头。
5. shim 停机 → `search` 降级成 unavailable、`remember` 抛错变 internal，**不静默返回空**。
6. 适配器不发多余字段（抓包/单测断言 payload 只含契约字段）。

## 10. 待决问题

1. **`session_id` = `memoryBodyId` 的粒度**：会话展开因此几乎失效。若将来要多用户/多空间，需要重新设计"会话"的表达（可能需要 discover 返回多个空间）。
2. **`list` 的实现深度**：`browse:false` 时是否仍要提供"按空间浏览"？当前计划返回空；若 GUI 依赖 list 展示，需补最小实现。
3. **provider 包的分发**：仅 bundle patch / 手改 `cordis.patch.yml`。是否要做成可提交到官方源列表的 `dsh-mnemon-source-*` 命名（05 §1 说 GUI 只认这个前缀）——命名会掩盖"它不是 source 而是 provider"，需权衡。
