## 1. 一句话与现状

**factlayer 是 dsh-mnemon 的一个记忆后端**：Python shim（SQLite 事实层 + 派生层）+ TypeScript provider 适配器，两台机器共享一个 ECS 实例。核心纪律：**事实层只追加永不改，派生层随时删光重算，写入不做任何判断**。

| 项 | 现状（2026-11-12 实测） |
|---|---|
| 仓库 | `github.com/PAustralis/dsh-mnemon-provider-factlayer`（公开，MIT） |
| 代码量 | Python 20 模块 / TS 11 模块 |
| 测试 | **246 Python + 91 TS 全绿** |
| 提交 | 50+（历史见 `git log`） |
| 后端 | 阿里云 ECS `i-2ze07ji23vhqjm1nwrb9`，systemd `factlayer.service`，监听 `192.168.168.2:8000` |
| 数据 | `/var/lib/factlayer/facts.db`，**目前只有 3 条联调测试记忆** |
| 接入 | Windows DSH profile + 网吧 VM（bogon）各装一个 provider，`baseUrl` 都指向 ECS |
| 契约插件 | 已实现、已构建、**未装载**（`docs/12` 顶部有"禁止安装"） |

**能跑通的闭环**（已实测，不是设计）：Windows 写入 → ECS 落库 → Windows 召回；VM 写入 → ECS → Windows 召回。回执为 `action:"stored"`（不是 `unknown`）。

## 5. 决策时间线（为什么是现在这样）

1. **先建事实层**：只追加 + 触发器强制 + `seq/gseq` 分离。`seq` 是会话内序号，`gseq` 是全局单调（VACUUM 后不变），两者不能混。
2. **检索层先做实测再做设计**：用 119 条真实语料 + 40 题跑 recall@6，发现二元组最强（0.4875）、trigram 对 1–2 字查询静默 0 命中、unicode61 完全不可用。据此定单混合列方案。
3. **真实 embedding 推翻替身结论**：TF-IDF 替身下"融合无增益、MMR 惰性"；真实 embedding 下 R@4 0.8125、融合 −0.19、MMR −0.067。**默认改成 vector 单路**。
4. **契约 v2→v3→v4**：v2 把瞎答压到 1 但把 7 道该答的题变成反问；v3 修好但边界过宽；v4 压线达标（❌ 2、✅ 26）。
5. **外部效度打脸**：v4 在 LongMemEval 上不成立，knowledge-update 崩 30pp → 标记禁止安装，v5 草案 + held-out 闸门写进 `docs/17`。
6. **题库改造与审查**：LongMemEval 转换 → glm 审出重复 fact_id 与泄漏 → 修 + 全量筛查 → 337 干净题。
7. **MMR/展开翻案**：大池 + 小输出 + 大语料下，两者都是正增益（+2.4pp / +4.5pp），但**产品还没实现**。

被否决/不做的东西（附依据）：
- 写入时 LLM 判断、冲突检测、相似度去重、软删除（违反"零人工维护/写入不判断"）
- 图数据库当事实存储（FalkorDB 只留空壳，实体抽取是 stub）
- ANN 索引（数千条规模 numpy 暴力毫秒级）
- 时间衰减/最新优先排序（与"最近 50 条"实测负增益冲突）
- 契约 v4 装机（外部不成立）
- RRF 融合（实测 −0.19）

## 6. 关键设计决策（改了会出事的）

1. **事实层不可变**：任何"更新/删除"都靠追加；`supersedes` 只追加，撤销用 `kind=revoke`。
2. **作废语义是 per-pair 最新边**，不是"有 supersede 就作废"；被作废记录**不排除**，而是在每路内部 RRF 之前用"存活纠正者"替换名次；出口断言保证不泄漏。
3. **`gseq` 与 `seq` 分离**：`seq` 会话内序号（回执/展开用），`gseq` 全局单调（tie-break 用），迁移时重建表并回填。
4. **索引文本 = 日期前缀 + 正文**（`INDEX_TEXT_VERSION=2`）：前缀同时喂 embedding 与 BM25，`content` 一字不动；版本落后时后台重建。
5. **默认 `RETRIEVAL_ROUTES=vector`**：二元组只在向量不可用时降级；不要在没有实测的情况下改回融合。
6. **输出契约**：FINAL_K=4、单条 1200、总 4800、每条数值 score、`createdAt` ISO、状态只走 tags、空结果 `hint` 以 `NO_MATCH` 开头。
7. **回执**：`{action:"stored", committed:true, count:1, memoryBodyIds, ids}`；**绝不加 `memoryReceipt`/`completion` 键**（Host 有更严的校验通道，见 `docs/21`）。
8. **契约 v4 不装**：`docs/12` 顶部的禁止标记是硬规则；装载机制在 `plugin/cordis.patch.yml` + `plugin/src/contract-plugin.ts`，但 `dsh.profile.bundles` 里不许出现它。

## 8. 下一步建议（按优先级）

### 8.1 先做：MMR + 会话展开（有实测支撑，改动可控）

- **MMR**：在 `app/retrieval.py` 对 top-50 做迭代 MMR（λ=0.7，余弦多样性）再取 4；预期 +2.4pp（CI [+0.003,+0.045]）。风险：λ 需固定，pool 必须 50（池 20 时无增益）。
- **会话展开**：当前实现"占名额、只在不足 4 条时触发"，**必须改成"不占名额的附加上下文"**才有效（预期 +4.5pp）。代价：输出从 4 条变平均 9.5 条，4800 字符预算会截断——需要重新设计 payload（例如只附最近 1 条邻居、或邻居只给摘要）。
- 两者都要过 glm 代码审查 + 246/91 测试 + 真实 shim 冒烟。

### 8.2 生产就绪三件（sonnet 建议，我认同）

1. **规模验证**：把 LongMemEval s 的 246,595 条事实灌进真实检索，测 P50/P95 延迟、灌库/重建耗时、备份耗时、R@4 衰减。**这是目前最大的未知**——所有结论都来自 119 条。
2. **outbox + 恢复演练**：断网/超时/重启/重复提交的故障注入，再从备份真实恢复一次并对比。
3. **真实使用日志**：记录 query、返回 id、是否被引用；两周后看 NO_MATCH 率、重复提问率、采用率，再决定是否做弃权校准/场景元数据/v5。

- 会话展开与 MMR 实现后，③ 层才算真正收尾；其余（图邻居/trigram）继续不做，理由：零数据或负增益。
- 契约 v5：只在真实日志出现"隐式累计更新"导致的错误后再做；现在做是为一个评测现象打补丁（sonnet 原话）。

## 9. 运维手册

### 9.1 ECS 服务

```bash
# 状态
systemctl status factlayer --no-pager
curl -s --max-time 5 http://127.0.0.1:8000/health | head -c 400
# 升级代码（本机打包 → workbench upload → 解包重启）
# 本机： tar -czf app.tar.gz app && workbench upload app.tar.gz /root/ ...
# ECS：  cd /opt/factlayer && tar -xzf /root/app.tar.gz -C . && systemctl restart factlayer
```

- 部署通道：本机 `workbench` CLI（阿里云 Workbench），`workbench list -r cn-beijing` / `exec` / `upload`。
- ECS 上 `git clone` GitHub 会 TLS 失败，**用 tar 包上传**。
- 防火墙：nftables 需放行 `iifname "tun0" ip saddr 192.168.168.0/24 tcp dport 8000`（已写进 `/etc/nftables.conf`）。
- 本机访问 ECS 内网地址必须 `-NoProxy`（否则被 Clash 代理成 502）。

### 9.2 Windows profile

- provider 以 **junction** 方式装在 `~/.dsh/profiles/web/node_modules/dsh-mnemon-provider-factlayer` → `plugin/`
- `providers` 列表属于 **`mnemon-source-memory-spaces` 子条目**，不是 `mnemon` 主条目；patch 整块替换，必须重复 9 个默认 provider
- `baseUrl` 在 `~/.mnemon/state/memory-providers.json`，**改后必须重启后端**（运行中缓存旧值）
- **不要**用 `install_bundle` 装本包（会把 junction 变 `file:` 依赖，回滚还会断 provider）；回滚＝删 `dsh.profile.bundles` 里那行 + 重启

### 9.3 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 空间一直 unhealthy | provider 没装配 / baseUrl 不通 | 看 DSH 日志、`curl /health` |
| 模型说"没记过"但库里有 | 检索未命中 / 向量熔断 | 看 `/health` 熔断、`degraded`、`tags` 里的 `vector-unavailable` |
| 写入后模型说 `action: unknown` | 回执形状不对 | 检查 adapter 回执；**不要加 `memoryReceipt`/`completion`** |
| `/search` 503 rebuild | 索引重建中 | 等 `rebuilding=false`；`/health` 可见 |
| 余额耗尽/402 | 评测或日常调用 | 先查 `https://api.deepseek.com/user/balance` |
